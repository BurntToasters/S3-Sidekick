## Versioning

S3 Sidekick follows semantic versioning. Stable releases use `X.Y.Z`; pre-releases use `X.Y.Z-beta.N` or another explicit pre-release identifier. Release proof binds the tested working tree, commit, lockfiles, platform, and toolchain. Release commands require local quality-gate and build-session proof; GitHub Actions run status is not release authority. Uploaded artifact and signature verification remains mandatory.

## Platform and frontend baseline

The frontend build targets Safari 16.4 in `vite.config.ts` (`build.target` and `build.cssTarget`). The UI depends on CSS container queries (`@container`) and `color-mix()`, so `bundle.macOS.minimumSystemVersion` is 13.3, the first Ventura release that ships Safari 16.4. Lowering the deployment target requires replacing those features or shipping CSS fallbacks first. Windows uses the evergreen WebView2 runtime; Linux needs a WebKitGTK 4.1 build with the same CSS features (2.40 or newer for `color-mix()`).

## Generated files

`npm run licenses` writes `public/licenses.json` and `public/licenses-cargo.json`; both are gitignored and regenerated by `tauri:dev`, `tauri:build`, every host build script, the Flatpak build, and CI. Do not commit them. `license-checker` records absolute `path` and `licenseFile` values under the build checkout; `scripts/generate-cargo-licenses.js` strips both before the files are bundled, so a release never publishes the builder's home directory. `scripts/sync-version.js` maintains the AppStream release list. The checked-in `src-tauri/permissions/autogenerated/*.toml` files are emitted by `tauri-build` from the command list in `src-tauri/build.rs`; regenerate them with `cargo check --manifest-path src-tauri/Cargo.toml` (or any Tauri build) and review the diff instead of hand-editing.

## Storage flow

The webview owns presentation state and sends named commands through Tauri. The Rust backend owns S3 clients, credentials, filesystem access, transfer checkpoints, and vault migration. Connection and listing generations prevent late async responses from changing a newer destination.

Upload keys and the case-fold collision check normalize names to NFC with the `unicode-normalization` crate (0.1.25, Unicode 17.0). It replaced about 3,500 lines of embedded tables that had no generator or recorded Unicode version, after an exhaustive comparison over every scalar value showed no difference (`test-results/nfc-equivalence/report.json`). A crate update that changes the Unicode version can change the key derived for a newly assigned character, so review the release notes before bumping it.

The S3 endpoint is resolved and every address checked once, at connect (`validate_endpoint_resolution`). The AWS SDK resolves the host again for each request, so a DNS answer that changes after connect (rebinding) is not checked again; pinning the checked addresses needs a custom resolver in the SDK client. SFTP dials the addresses it checked.

Webview module boundaries avoid runtime import cycles. `app-layout.ts` renders the object table through `layout-render-bridge.ts`; preview and properties call the inspector through `inspector-host.ts`; and transfer row/chrome rendering lives in `transfer-render.ts` rather than the queue and recovery flow.

Unhandled promise rejections in the webview are caught by a global `unhandledrejection` reporter (`src/async-errors.ts`) as a safety net. It shows a friendly status line and an activity-log entry, and the console keeps the raw error. Click handlers should still catch their own failures and name the action through `reportAsyncActionFailure` in `src/async-action-report.ts`, so the message says what failed.

## Transfer integrity

Uploads use S3 checksums when enabled. Large downloads use range requests pinned to a readable object version selector, including the literal `null`, or to an ETag when version IDs are unavailable. Resume checkpoints retain that identity and are rejected when the object generation changes. Copy receipts record source and destination ETags/version IDs plus canonical source HEAD, ACL-grant, and raw-tag fingerprints. Supported empty ACL/tag state is fingerprinted differently from a provider that explicitly reports the feature unsupported; ordinary read failures fail closed. Receipt-producing copies collect all three source fingerprints even for small objects.

Automatic moves require a provider with verified `DeleteObject If-Match` behavior. The current matrix grants that authority only to Amazon S3. Other providers, including the pinned MinIO server, retain sources and refuse moves before destination mutation wherever the move command can make that decision. Ordinary copies and downloads remain available; explicit overwrite copies are not blocked by the move policy. The literal `null` remains a readable version selector but is mutable while versioning is suspended, so it never authorizes an automatic move or a version-targeted rollback delete. A versioned move must bind a non-null version ID; an unversioned source may move only on a provider with verified conditional DELETE support. When source HEAD omits a version ID, unversioned move deletion also requires `s3:GetBucketVersioning` so the backend can rule out enabled or suspended bucket versioning; if that lookup is denied or fails, deletion is refused and the source is retained.

Move receipts persist only complete version 6 records. Version 1-5 copied markers and malformed version 6 receipts lose copied authority and must copy again. After reacquiring one mutation lease for the complete receipt set, the backend rejects missing fingerprints and verifies every destination. It classifies the complete source set before the first delete, then rechecks each source and destination immediately before that item's conditional delete. This prevents an already-visible later conflict from deleting an earlier source; it does not make a multi-object move atomic against later external writes. With versioning enabled, deleting the key writes a recoverable marker and retains the copied non-null source version. Unversioned moves use ETag-conditioned deletion and are limited to the verified provider matrix.

Every S3 command requires the backend-minted connection session ID from the current `connect()` call. Transfer records persist that session ID plus a fingerprint of endpoint and access key. After reconnect or restart, a transfer whose fingerprint does not match the current account is refused rather than running against a different set of credentials.

ETags are provider-defined object identities, not universal content hashes. An external writer is outside S3 Sidekick's process-local lease, so source deletion and unversioned rollback require the provider to enforce the supplied `If-Match` condition. A failed check retains the source or rollback backup. ETags do not distinguish metadata-only changes; unversioned operations also compare collected fingerprints immediately before deletion, while the final provider condition is limited to ETag semantics. A literal `null` version is separately excluded because suspended versioning lets a write replace that generation in place.

Prefix copy and move operations first build a complete, duplicate-free, paginated source plan within the bounded object limit. Move plans reject mutable null versions before destination mutation; ordinary copy plans keep readable-version compatibility. On providers without verified conditional DELETE, an overwrite prefix transaction first classifies every mapped destination and refuses before mutation when an occupied destination is in an unversioned or suspended bucket. It can proceed when versioning is Enabled and rollback objects receive exact non-null version IDs. The ordinary single-object explicit overwrite path remains available. Unversioned source deletion classifies the complete receipt set before its first DELETE and retains final per-item checks. Rollback deletes exact non-null response-owned versions directly; unversioned rollback uses conditional DELETE only on a verified provider and otherwise retains the destination or backup for recovery.

## IPC contract and access control

`src-tauri/src/ipc_contract.rs` generates `src/generated/ipc-contract.ts` from every command registered in `generate_handler!`: the command name and its argument keys (camelCased, as Tauri reads them), types, and optionality. A Rust test fails when the checked-in file drifts. The webview calls native commands only through `src/ipc.ts`, whose `invoke` is typed against that contract (ESLint forbids importing the raw `invoke`). The Playwright mock backend is typed against the same command set.

`build.rs` declares an app manifest, so every app command gets an `allow-<command>` permission that only `capabilities/default.json` grants, through the permission sets in `permissions/app.toml`, and only to the `main` window. `src/ipc_acl.rs` runs Tauri's own access check against the real capabilities: every registered command is allowed for `main`; unknown commands and other windows are denied; and the build.rs list must equal the registered list. Core and plugin commands are granted individually rather than through `:default` sets: app version, event listen/unlisten, the window methods used by the title bar and window-size restore, dialog message (ask is an alias), notification permission, updater check/download/install. Process restart has no plugin grant: it goes through the `relaunch_app` app command, granted via the `platform` permission set. `tauri.dev.conf.json` keeps the production updater endpoint out of development and disables updater artifacts.

AppStream screenshots live in `docs/screenshots/` with a capture-version note and regeneration commands. `scripts/screenshots.test.js` checks the AppStream URLs against the branch that ships them and checks the PNG dimensions, so a stale or 404 screenshot fails the script suite.

Show in folder for a completed download calls `reveal_local_path`, which takes the row's stored destination. It only shows the file: macOS runs `open -R` and Windows runs `explorer /select,`, and on Linux, where file managers cannot select a file, it opens the parent folder. Relative, missing, and symbolic-link paths are refused on every platform, and a bundle directory is refused on macOS. Nothing in this path runs the file: the selecting openers only highlight it, and the Linux opener receives only the folder.

## Cancellation and transfer state

A transfer registers with the backend (`TransferGuard`) before it waits for the storage gate, so pause and cancel reach it at any point. A `cancel_transfer` that arrives before registration is kept for 30 seconds (at most 4,096 entries) and cancels the next command with that ID. The frontend treats the resulting cancellation as the pause it came from (`pauseCancelInFlight`), not as a failure.

Queue rows change status only through the named transitions in `src/transfer-state.ts`, checked against a table of legal moves (`queued → uploading → done`, with side exits to `error`, `skipped`, and back to `queued`). An illegal move throws in development and tests. The queue loop and the worker claim share one `isClaimable` predicate and one `queueHeld` predicate, so the loop never spins on work that nothing may claim.

## Selection identity

The webview keeps files in `state.selectedKeys` and folders in `state.selectedPrefixes`. Every row, click and inspector path passes a `{ kind, key }` entry (`src/app-selection.ts`), and the row's `kind` comes from its dataset (`data-key` for files, `data-prefix` for folders), never from the text of a key. A legal object key such as `prefix:archive` is a file. Folder keys are always the trailing-slash prefix S3 returned, and native prefix delete refuses a prefix without that slash (`validate_mutating_folder_prefix`), so a bare `archive` cannot match `archive.zip` or `archived/…`.

## Create-only retries

A create-only write can commit while its response is lost; the SDK retry then gets 412 against its own object. Uploads recognise their own write by size plus the SHA-256 ownership marker in metadata. Copy create-only is advertised only where the destination condition is documented and supported: the pinned MinIO server is excluded because it accepts an occupied CopyObject destination despite `If-None-Match`. Ambiguous copy completion fails without issuing a successful receipt. Persisted receipts record destination ownership ambiguity; missing legacy ownership claims are treated as ambiguous and cannot authorize source or rollback deletion. These move rows require inspection and reconciliation before removal. Providers without atomic create-only copy require explicit overwrite authorization; ordinary explicit overwrite remains supported.

Upload recovery is an upload-only ownership check, not deletion authority. Size plus the SHA-256 metadata marker, or a matching content-MD5 ETag on a single-part PUT, only decide whether a retried upload already committed; they never authorize removing a source. A bucket writer can spoof the marker, so moves and renames continue to require the ETag-bound copy receipt before any conditional delete.

## Move capability exposure

A move retires its source only on providers whose `DeleteObject` honours `If-Match`. The native `connect` result reports this as `conditional_delete_supported` (from `supports_conditional_delete` in `src-tauri/src/s3/create_only.rs`), and the webview stores it in `state.conditionalDeleteSupported`. The flag is false until a connect result says otherwise and is cleared on disconnect, so a missing field disables Move. It only gates the UI: the native transaction path checks the same provider rule before deleting a source, so a webview that ignores the flag still cannot retire an unverified source.

The provider is chosen from the endpoint hostname (`detect_storage_provider`). AWS authority goes only to S3 object API hostnames (`s3`, `s3.<region>`, `s3-<region>`, dualstack, FIPS, Transfer Acceleration and interface VPC endpoint forms, in both partitions), not to every `amazonaws.com` host. EC2 public DNS names, load balancers and API Gateway hosts share the suffix and can front any S3-compatible server, so they are Generic. S3 on Outposts, Object Lambda, access point and Express One Zone hosts are also Generic until their conditional behaviour has an E2E contract. The hostname is still a claim, not evidence: a connect-time capability probe would replace it, and the MinIO guess (a `minio` host label or loopback port 9000) has the same limit.

## Lock order

Synchronous locks are taken in one global order, outer to inner: the storage gate and `STORAGE_OP_LOCK` (`lock_storage_meta`, `lock_storage_ops`), the cross-process vault file lock, the S3 session state, then the vault key. `src/lock_order.rs` checks this order in debug builds (every test run) and costs nothing in release builds. The async S3 mutation leases are awaited, never held under these locks, and are not ranked.

## Auto-lock

The backend expires the vault key lazily. The webview polls the vault state and, when an inactivity timeout has locked it, disconnects the session and clears decrypted credentials and bookmarks from memory. Pointer and keyboard input count as activity, and so do running transfers: the timeout starts once the queue is idle, so an unattended transfer is never interrupted.

Manual **Lock now** has one flow, `runManualLockNow` in `src/app-events.ts`, which Settings and the header switcher both run. The switcher reaches it through `setLockNowHandler` in `src/app-connection.ts`, which avoids an import cycle. Auto-lock and manual lock both end in `teardownLockedSession`, so dialogs, the preview, the inspector, inline edits, and revealed secrets are handled the same way on either path.

## Testing layers

End-to-end suites are the primary evidence and each writes a repeatable report under `test-results/`: Playwright drives the production webview against a mock backend typed by the IPC contract (`npm run test:ui`); the MinIO suite runs the Rust S3 command layer against a real server (`npm run test:e2e:minio`, in CI); the SFTP suite runs the Rust SFTP command layer against an OpenSSH container on a digest-pinned base image (the report records the installed `openssh-server` version) (`npm run test:e2e:sftp`, in CI as `sftp-e2e`, report at `test-results/sftp-e2e/report.json`); script suites cover release and dependency tooling (`tests/scripts/`). Unit suites (Vitest for the webview, `cargo test` for Rust) cover pure logic and failure paths that the end-to-end layers cannot reach.

## Preview policy

Text previews are capped at 1 MiB: larger text objects are read with a ranged request and returned truncated. Images have a separate 16 MiB cap and must arrive whole; an image above the cap, or one whose body streams past it, is refused rather than returned as a partial image. Every read is streamed with a hard one-byte overflow check. Text detection ignores parameters such as `; charset=utf-8` and recognizes `text/*`, JSON, XML, JavaScript, SVG, YAML, and TOML. The webview renders Markdown as plain text and never as HTML, so previews need no CSP change. PDF, audio, and video are offered as downloads; previewing them would require a CSP or asset-protocol decision. Other content is offered as a download rather than rendered as text.

## Object actions

`src/object-actions.ts` is the single registry of object actions (`id`, label, icon, shortcut, danger, group, availability, run). The row context menu, the selection bar's **More** menu, and the command palette's selection commands all render from it, so an action has one label and one availability rule. Shortcut hints come from `SHORTCUTS` in `src/shortcut-catalog.ts`, never from a second list.

## Layout preferences

Row density is a CSS token: `--row-height` is 36px, and `html[data-density="compact"]` sets it to 28px. The object table's virtualization reads the computed value and re-reads it when the attribute changes. The inspector opens by default only when the listing container is at least 1280px wide and the user has no stored open or closed choice; an explicit toggle is stored and always wins.

## Connection location memory

Each saved connection remembers its last bucket and prefix in local storage under `s3-sidekick.connection-memory`, keyed by the connection name and endpoint only. Credentials, session IDs, and secrets are never part of the key or the record. The memory is restored when the user switches connections and is forgotten when the connection is removed. **Test connection** connects, lists buckets, and disconnects; it never keeps the resulting session.

## SFTP sessions

SFTP is a second connection type beside S3. It shares the session authority in `S3State`: the backend-minted connection ID, the connection identity (SHA-256 of `sftp://host:port` and the username), and the `sftp` field. An SFTP session leaves the S3 client empty, and an S3 session leaves `sftp` empty, so each command family fails closed on the other kind. SFTP has its own `sftp_*` commands. The webview maps the server onto the bucket and key model as one virtual bucket named after the host; copy and S3-only actions are hidden.

- **Connect is a backend state machine.** `sftp_connect`, `sftp_connect_continue`, and `sftp_connect_cancel` drive the handshake, which cannot be replayed. One attempt is pending at a time, and a newer connect cancels the older one. A user wait lasts at most 120 s. Disconnect, vault lock, and a newer connect cancel the attempt's token.
- **Every connect step is bounded.** DNS gets 10 s. TCP connect has one 10 s budget for the whole attempt. The resolved addresses are tried in order, and each gets an equal share of the budget, split across at most three addresses (two addresses get 5 s each). A refused address moves on at once, so a dual-stack host whose first address (often IPv6) does not answer reaches the next address. The SSH handshake (banner and key exchange) gets 30 s, because russh reads the server banner with no limit of its own; the clock pauses while the user decides whether to trust the host key. Authentication requests get 60 s, and channel, subsystem and home steps 15 s.
- **Cancel reaches an attempt before its first step.** Until `sftp_connect` returns a step, the webview has no attempt ID. The Cancel button therefore calls `sftp_connect_cancel_pending`, which cancels whatever attempt is pending (there is one slot and one connect form). A cancel epoch also catches a connect that has entered the command but not yet taken the slot. The webview checks its cancel flag before each dialog and each reply, so a cancelled attempt opens no trust or sign-in dialog.
- **A late install can briefly outlive a superseded connect.** If the webview supersedes an attempt just after the backend installed its session, that SSH session stays open until the webview releases it or the next connect replaces it. S3 has the same shape. The fix belongs to the shared connect flow, not to SFTP.
- **Host keys are pinned per saved connection or bookmark.** The first key is shown for trust and then stored with the connection, so no new vault file exists. A changed key is refused. Only an explicit reset clears the pin.
- **RSA is excluded.** Client host-key preferences offer only Ed25519 and ECDSA (P-256, P-384, P-521), and user keys omit RSA. A server that offers only RSA host keys fails with a message that names the supported types. The `rsa` crate carries unpatched RUSTSEC-2023-0071, so russh is built with only `aws-lc-rs` (see [DEPENDENCY_UPDATES.md](DEPENDENCY_UPDATES.md)).
- **Private keys are read once in the backend.** The native dialog grants a path, and the backend reads it once: a regular file, no symlink, at most 16 KiB. The key text is returned for the saved connection, so connect never reads a second file.
- **Reconnect falls back to home.** After connect, the app opens the remembered folder for the connection. If that folder cannot be opened, missing or refused, it opens the home folder and says so with a notice. A lost connection keeps the lost-connection handling and does not fall back. If home also fails, the retry banner stays, and Retry runs the whole restore again, remembered folder first.
- **Dropping the session closes the socket.** Dropping the last `SftpHandle` cancels its shutdown token, which drops the TCP socket. No SSH DISCONNECT is sent.
- **Lost connections are named.** An error from a closed transport starts with `SFTP connection lost`, so the webview can disconnect and offer reconnect. Each SFTP request times out after 45 s (the crate default of 10 s failed slow fsyncs). A request that times out means the server stopped answering, so the session closes its socket and reports the loss; the limit is below the 60 s download idle limit, so a dead link reads as lost, not stalled, and queued transfers park.
- **Hardlink support is probed without side effects.** The connect step sends `hardlink@openssh.com` with a source that does not exist, so the server can only answer with an error and creates no link. Only "no such file" counts as support; a refusal reads as unsupported. Create-only upload finalize hardlinks the temp file when the extension is present. Otherwise it runs lstat then rename, which leaves a race between the check and the rename. A hardlink that fails while the target is still absent (an advertised extension on a filesystem without links, such as FAT or exFAT) falls back to the same lstat then rename. OpenSSH stops advertising the extension when `sftp-server -P hardlink` denies it; the E2E fleet's fifth port uses that to run the no-hardlink path.
- **Uploads stage, then finalize.** Data goes to `.<name>.s3sk-<hex>.part` before finalize. A connection dropped mid-stream can leave that temp file on the server.
- **Overwrites keep the target's permissions.** The temp file of an overwrite is created at 0600, so the new bytes are never readable by more users than the file they replace, and it is given the target's permission bits (without set-user-ID, set-group-ID, or sticky) through the open handle before the swap. Ownership is not carried over: the new file belongs to the login. A new file gets the server's default mode, as `sftp put` gives it, because the client cannot read the server's umask. If the server refuses the permission copy (fsetstat), the upload fails before the swap. The existing file is kept unchanged, and the message says to delete the remote file and upload again.
- **A symlink is never replaced by an upload.** An overwrite upload onto a symlink is refused, with a message that names the link. `sftp put` writes through the link instead; beta.1 asks the user to upload to the file the link points to.
- **Overwrites swap through a backup.** The old file is renamed to `.<name>.s3sk-bak-<hex>`, the new file is renamed into place, and the backup is restored on failure. The swap is not atomic.
- **Leftover files are reported.** When an upload or rename succeeds but its backup or hardlinked temp name cannot be removed, the command returns a `warning` that names the leftover path. The webview writes it to the activity log and shows a toast that stays until dismissed. If the app stops between the two renames of a swap, the target name is absent and the old content is in the `.s3sk-bak-` file next to it; rename that file back to restore it. The settings SFTP note says the same.
- **Downloads resume from a versioned checkpoint.** The scratch file uses the existing download scratch path. The SFTP checkpoint carries a protocol marker and a version (2). It resumes only when path, endpoint, username, size, and mtime match, and the scratch identity and length match too; a server that chroots each user gives one path a different file per user. A version 1 checkpoint has no username and restarts from zero. A remote change during a download fails closed.
- **Listing uses lstat semantics.** A listing caps at 5,000 entries. A symlink is listed with its own size and is not followed, and a symlinked folder cannot be browsed.
- **Non-UTF-8 names are read-only.** russh-sftp 3.0.1 decodes such names lossily, so they are listed with `name_lossy`. Every mutating command refuses a path that contains U+FFFD.
- **Recursive delete is bounded.** It never follows symlinks, it is bounded by `MAX_PREFIX_TRANSACTION_OBJECTS`, and it refuses `/`, the home folder, and any ancestor of home. The walk trusts READDIR attributes only to say an entry is not a folder; an entry they report as a folder is checked again with lstat, because the protocol does not promise lstat semantics for READDIR.
- **Authentication failures name the accepted methods.** When the server's list of accepted methods does not include the method the user chose, the error reads `Authentication failed. This server does not accept <method> sign-in for this user. It accepts: <list>.` Known method names are shown as labels and unknown names as the server sent them. Otherwise the message stays `Authentication failed.`. The method names are the only server text shown.
- **Preview type comes from the file extension.** SFTP stores no content type. The type is taken from the extension, using a table that covers common text, config, log and source files. A file with an unknown or no extension (for example `README` or `.bashrc`) that is not a known binary extension is read under the 1 MiB text cap. It is shown as text only when its bytes have no NUL byte and are valid UTF-8; an incomplete final character at the cap is allowed. Otherwise preview is not available. Known binary extensions are never read for this check.
- **Conflicts are matched by a fixed prefix.** The native refusal for an existing target starts with `Remote path already exists: `. The webview treats only that prefix as a conflict (`SFTP_ALREADY_EXISTS`), so another error for a path that contains those words is not misread.
- **Folder downloads are one level deep.** Only regular files directly inside the folder are queued. A subfolder needs a local folder that the destination grant cannot create, so it is reported as skipped, not flattened. Symbolic links and names that are not UTF-8 are also reported as skipped.
- **Known beta gaps.** Folder delete has no cancel control. The saved last-connection record keeps its old host-key pin until the next successful connect rewrites it.

## Vault and biometric storage

Saved connection data, bookmarks, transfer manifests, and checkpoints follow the vault encryption state. Migrations use a journal and an exclusive storage gate so a rekey/reset cannot race transfer checkpoint I/O. Biometric unlock currently gates access through the OS credential store as defense in depth; it is not a hardware-bound Secure Enclave or Windows Hello key.

Payload metadata, the security policy and the factory-reset journal are authenticated with HMAC-SHA256 from the `hmac` crate, each under its own key derived as SHA-256(vault key ‖ label). The hand-written HMAC used before 0.13.0 produced the same tags; `hmac_sha256_keeps_the_tags_existing_vaults_were_written_with` pins them so existing vaults keep verifying. Known limit: AES-GCM payloads carry no associated data that binds them to their file, so a local writer can swap two valid payloads or restore an older one. Parsing usually rejects a swapped file; a rollback is not detected. Closing this needs a payload version 3 with the file role as associated data, and a migration.

## Update modes

Linux ships as an AppImage and a side-loaded Flatpak; DEB and RPM packages were retired in 0.12.0 because Tauri's RPM bundler cannot package prerelease versions and neither format had an update path. AppImage builds use the native updater. Flatpak installations, and any remaining DEB or RPM installations, use the release page because replacing sandboxed or package-managed files through the native updater is unsafe. Updater manifests contain Minisign signatures verified against the public key configured in `src-tauri/tauri.conf.json` before release upload.

The frontend unit suite enforces global coverage floors for lines, functions, statements, and branches. Native Tauri/WebDriver behavior still requires the signed desktop build matrix because it depends on OS credential stores, windowing, and real provider responses.

## macOS restart

Restarts after an update install, a settings reset, or corrupt-settings recovery call the `relaunch_app` app command (`src-tauri/src/platform.rs`). The plugin relaunch ran `open -n` while the old process was still alive, so a pinned Dock icon gained a second S3 Sidekick. On macOS, when the executable sits directly inside `<X>.app/Contents/MacOS/`, the command spawns a detached `/bin/sh` helper in its own process group with null stdio. The helper polls `kill -0 <old pid>` every 0.1 s for at most 600 polls (about 60 s), then runs the absolute `open` launcher, resolved by `unix_launcher`, on the bundle path without `-n`. The app then calls `app.exit(0)`. The PID, bundle path, launcher path, and poll limit are positional arguments and are never interpolated into the script.

Failure-mode inventory:

- **Overlap:** the helper must never pass `-n`. It opens the bundle only after the old PID is gone, so LaunchServices activates the pinned instance rather than creating a second one.
- **Helper outlives the parent:** the helper is detached and must keep running after `app.exit(0)`, so it cannot depend on the parent's stdio or process group.
- **PID reuse or a stuck old process:** the wait is bounded. On timeout the helper exits and launches nothing; the user starts the app manually.
- **Path metacharacters:** spaces, quotes, `$`, and non-ASCII characters in the bundle or launcher path reach the helper only as positional arguments.
- **Dev run outside a bundle:** falls back to `app.request_restart()`. Overlap is accepted there because development builds are not pinned.
- **Bundle-root detection:** only an executable directly under `<X>.app/Contents/MacOS/` takes the helper path. Any other layout falls back.
- **Launcher unresolvable or spawn failure:** falls back to `app.request_restart()`, which may overlap. This is the known residual case.
- **Windows and Linux:** use `app.request_restart()` directly. The Dock duplication is macOS-specific.
- **Frontend call sites:** `src/updater.ts` (after install), `src/settings.ts` (reset), and `src/app-init.ts` (corrupt-settings recovery) call `relaunch_app` through `src/ipc.ts`. When the call rejects, each keeps its existing webview-reload fallback.
