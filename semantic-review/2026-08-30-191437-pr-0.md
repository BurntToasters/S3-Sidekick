# Descriptor-bound multi-host release hardening with immutable publication

The release flow coordinates all hosts around a signed descriptor, generates signed host evidence, uploads immutable draft assets, freezes the asset set with a signed index, and verifies the published release anonymously. The target-owned install-smoke/SemVer blocker and Windows Authenticode skip blocker are closed. The signed-index blocker is only partially closed: indexed payloads get fresh GitHub-digest checks, but the index and signature defining the freeze can disappear or change unnoticed. Source identity, pre-publication tag identity, macOS trust coverage, updater URL identity, and GPG passphrase transport add further blocking gaps.

Watch for: **[P1, confirmed]** fresh index rechecks ignore the index/signature pair; **[P1, confirmed within the reviewed files]** the descriptor binds `HEAD` while Flatpak builds the mutable working tree; **[P1, confirmed]** tag identity is checked only after publication; **[P2, confirmed]** macOS trust reports need not cover any final package; **[P2, confirmed]** updater URLs can target another release tag; **[P2, confirmed]** GPG passphrases are exposed in child command arguments.

**Verdict**: NEEDS_CHANGES

## High-level view

The **[P1, confirmed within the reviewed files]** source-binding gap is that the descriptor hashes committed `HEAD`, but no reviewed gate requires a clean checkout or constructs the build from that archive. Flatpak copies the live tree, including otherwise eligible untracked files, into its build context.

The signed index gives each payload an immutable digest, but the **[P1, confirmed]** freeze-marker gap excludes the index and its detached signature from all fresh authenticated and anonymous metadata comparisons. Their loss or replacement can survive the last check before publication or the last anonymous recheck.

Install-smoke reports are constrained to package artifacts claimed by the attestation owning the target, and their digests must match downloaded release assets. Strict SemVer comparison handles prerelease precedence and requires a genuinely older `previousVersion`; Windows evidence rejects every non-empty signing-skip value before verification or passed evidence, while PowerShell still checks outer and extracted-runtime signatures.

The **[P1, confirmed]** tag race remains because publication checks the current GitHub tag only after making the draft public. Release metadata still binds `target_commitish`, but a conflicting existing tag can be detected only after the visibility transition.

The **[P2, confirmed]** macOS and updater gaps are fail-open validation asymmetries: an empty trust artifact list can accompany passed package evidence, and updater URLs need match only the repository’s generic release-download prefix rather than the descriptor’s exact tag.

The **[P2, confirmed]** credential gap places the GPG passphrase directly in spawned command arguments. Environment isolation protects unrelated build subprocesses, but not process-list inspection while signing runs.

## Descriptor identity does not constrain the build tree

**[P1, confirmed within the reviewed files]** `sourceCommit` and `sourceArchiveSha256` resolve and archive `HEAD`, while `validateDescriptorForCheckout` recreates that committed-state descriptor without checking tracked modifications or untracked inputs (`scripts/release-integrity.cjs:560-630,726-744`). `stageFlatpakSource` instead copies the live repository paths accepted by `shouldStage`, and the manifest builds that directory (`scripts/flatpak-bundle.js:146-176`; `run.rosie.s3-sidekick.yml:55-57`).

A temporary-repository probe changed a tracked file after commit and observed identical archive hashes; another showed `shouldStage` accepts an ordinary untracked root file. Artifacts can therefore contain bytes absent from the descriptor’s commit/archive while provenance claims that committed source. Require a clean tracked/untracked input set before descriptor creation and every build, or build from the descriptor-bound archive plus explicitly hashed generated dependencies.

## The signed freeze marker is omitted from fresh metadata rechecks

**[P1, confirmed]** `assertReleaseAssetIndexEntries` rejects index records naming `release-assets.json` or its signature, filters both from the fresh name set, and validates GitHub digest metadata only for `index.assets` (`scripts/release-publication.js:398-442`). The authenticated freeze/recheck paths and final anonymous recheck all use this helper (`scripts/release-publication.js:676-755,826-832`).

A focused probe passed both a listing with the pair absent and one with arbitrary replacement digests. Deletion or replacement after signature verification can survive the pre-publication check, and anonymous verification can return success from stale downloaded index bytes. Require both names in every recheck and compare fresh GitHub digests with the locally downloaded, successfully verified pair in `digestByName`.

## Tag/source identity is checked after publication

**[P1, confirmed]** publication freezes assets and PATCHes `draft: false` before `assertGitHubTagCommit` (`scripts/release-publication.js:896-954`). A tag created or moved during the multi-host build interval can override the release’s otherwise correct `target_commitish`; the post-PATCH failure then arrives after the release is public. Resolve and validate an existing tag immediately before publication, treating absence as the expected tag-creation case, and retain the post-publication check.

## macOS package evidence accepts uncovered artifacts

**[P2, confirmed]** the Darwin branch verifies only records present in `macos-trust.json`, never requiring a record for each final package, then records every package with `status: "passed"` (`scripts/release-evidence.js:180-207,263-267`). A focused probe supplied the required check names, an empty artifact list, and an uncovered DMG; passed evidence included the DMG. Require a one-to-one name/digest match between final macOS packages and trust-report artifacts, rejecting missing, duplicate, and extra records.

## Updater verification is not release-tag-bound

**[P2, confirmed]** `RELEASE_DOWNLOAD_BASE_URL` is allowlisted and used to construct manifest URLs (`scripts/release-env.js:107-123`; `scripts/gpg-sign.js:54-57,590-637`). Publication checks only the repository’s generic `/releases/download/` prefix plus a current basename/signature, not `descriptor.release.tag` (`scripts/release-publication.js:512-549`). A probe pointing a manifest at `v0.0.1` in the same repository was accepted. Parse the URL structurally and require the exact descriptor tag and artifact basename.

## GPG passphrases travel in argv

**[P2, confirmed]** artifact/evidence and descriptor/index signing append `--passphrase <GPG_PASSPHRASE>` to GPG arguments (`scripts/gpg-sign.js:966-983`; `scripts/release-integrity.cjs:747-790`). Use a dedicated inherited file descriptor or another non-argv GPG channel, while retaining environment isolation for non-GPG subprocesses.

## Prior blocker closure: target ownership, SemVer, and Authenticode

Install-smoke allowed names come only from the attestation owning the target and must resolve back to that target (`scripts/release-publication.js:289-315`). Report validation rejects empty ownership, duplicates, unowned names, digest mismatches, malformed versions, and `previousVersion >= currentVersion`, including prerelease ordering (`scripts/release-integrity.cjs:139-205,208-289`). **[confirmed]** Prior blocker 2 is closed.

Windows package evidence rejects any non-empty `SKIP_WIN_CODESIGN` before invoking PowerShell (`scripts/release-evidence.js:160-179`). The PowerShell verifier has no skip branch and validates timestamped publisher signatures on each outer installer and its single extracted runtime; strict build verification also compares extracted runtime bytes with the signed pre-bundle runtime (`scripts/verify-windows-authenticode.ps1:9-85`; `scripts/tauri-windows-build.js:151-191`). **[confirmed]** Prior blocker 3 is closed.

## Focused probes and platform limits
